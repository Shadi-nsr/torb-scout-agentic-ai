# Torb Scout

نمونه‌ی اولیه‌ی Torb Scout برای چالش ترب هکاتون Agentic AI استارکوچ است. این پروژه مسئله‌ی خرید حضوری در تهران را با یک عامل قابل توضیح حل می‌کند:

1. نیاز کاربر، بودجه، محدوده و شرط‌های خرید استخراج می‌شود.
2. محصول‌ها، آفرها و فروشگاه‌ها از دیتاست رسمی چالش به هم وصل می‌شوند.
3. گزینه‌ها بر اساس قیمت، تازگی تغییر قیمت، فاصله و ویژگی‌های فروشنده رتبه‌بندی می‌شوند.
4. نتیجه با کارت محصول، مقایسه‌ی کنارهم، پراکندگی فروشنده‌ها و دلیل پیشنهاد نمایش داده می‌شود.

قیمت ثبت‌شده با موجودی لحظه‌ای یکی نیست. رابط این نکته را در تمام مسیر تصمیم نشان می‌دهد و برای مراجعه، تماس با فروشنده را پیشنهاد می‌کند.

## اجرا با دیتاست کامل

دیتاست را از لینک رسمی چالش دانلود و از حالت فشرده خارج کن. سپس:

    cd outputs/torb-scout
    python3 scripts/ingest.py --data-dir ../../work/dataset --db data/catalog.db
    python3 app/server.py --host 0.0.0.0 --port 8080

بعد از اجرا، آدرس http://localhost:8080 را باز کن. اگر مسیر دیتاست متفاوت است، مقدار --data-dir را تغییر بده. اجرای سرور بدون catalog.db هم ممکن است و در آن حالت چند رکورد نمونه برای دموی رابط نمایش داده می‌شود.

## ساختار

- app/server.py: سرور HTTP، جست‌وجوی SQLite، عامل برنامه‌ریزی و APIهای محصول.
- scripts/ingest.py: ساخت SQLite و ایندکس FTS5 از سه فایل CSV.
- app/static/: رابط راست‌به‌چپ و واکنش‌گرا.
- data/catalog.db: خروجی محلی ingest؛ در گیت قرار نده.

## APIهای اصلی

- GET /api/search?q=...&budget_max=...&location=...
- POST /api/assistant با بدنه‌ی {"message":"..."} برای اجرای مسیر تصمیم عامل.
- GET /api/product/<product_id> برای دیدن آفرها و فروشنده‌ها.
- GET /api/meta برای شمارش داده و محدوده‌های قابل فیلتر.

عامل فعلی با ابزارهای قطعی جست‌وجو، فیلتر، مقایسه و رتبه‌بندی کار می‌کند تا دمو بدون کلید خارجی هم تکرارپذیر باشد. برای نسخه‌ی بعدی می‌توان یک مدل زبانی را در جلوی همین ابزارها قرار داد؛ قرارداد API ثابت می‌ماند و هر تصمیم همچنان با داده‌ی قابل مشاهده پشتیبانی می‌شود.

## سناریوی پیشنهادی دمو

1. عبارت «گوشی موبایل تا ۲۰ میلیون نزدیک فردوسی» را از چیپ یا نوار جست‌وجو اجرا کن.
2. مسیر چهارمرحله‌ای عامل را نشان بده: فهم نیاز، جست‌وجوی کاتالوگ، رتبه‌بندی و قدم بعدی.
3. فیلتر محدوده یا بودجه را تغییر بده و اثر آن را روی نتایج و نقشه نشان بده.
4. دو یا سه کارت را برای مقایسه انتخاب کن و تازگی قیمت، کمترین قیمت، تعداد فروشنده و گارانتی را کنار هم بخوان.
5. روی جزئیات یک محصول بزن تا عامل دلیل تماس با فروشنده قبل از حرکت را توضیح دهد.

## نکات تحویل

- ویدئوی دمو حدود پنج دقیقه باشد و خروجی قابل مشاهده، مسیر تصمیم و محدودیت داده را نشان دهد.
- سورس همین نسخه را در یک ریپازیتوری گیت قرار بده؛ من عمداً هیچ git push یا ارسال پاسخ به حساب کاربری انجام نداده‌ام.
- فایل CSV کامل به دلیل اندازه‌ی زیاد داخل ریپو نیست؛ لینک رسمی و دستور ingest در همین README آمده است.
